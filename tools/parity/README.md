# Render-parity harness

Dev-only tooling (not part of any published crate) that proves a change to the shared
engine — turbo-dom, turbo-dom-layout, turbo-dom-raster, turbo-dom-browser-env — keeps
turbo-html2pdf and turbo-surf output byte-identical, or changes exactly what it claims
to change.

It renders pinned inputs through built napi addons and compares sha256 manifests of
every output against a recorded **checkpoint**:

| corpus | addon | outputs |
|---|---|---|
| `html2pdf` | turbo-html2pdf napi | template fixtures (plain / PDF/UA / CMYK / PDF/A), conformance fixtures (PDF + `layoutBoxes`), image matrix |
| `html2pdf-svg` | same, built `--features svg` | same set |
| `html2pdf-extra` | turbo-html2pdf napi | xref documents, broken/odd images, PDF/UA renders of conformance + image pages |
| `surf` | turbo-surf napi | static `screenshot`/`screenshotSvg` + live `render` dumps (per element: rect, 11 computed properties, `elementFromPoint`, recorded throws) |
| `surf-extra` | turbo-surf napi | static screenshots of the extra inputs |

Inputs: `inputs/image-matrix` (generated by `bin/make-image-matrix.sh`, pinned by
`IMAGES.sha256`) and `inputs/extra` are this harness's own fixtures. Upstream inputs
(html2pdf fixtures/conformance pages, turbo-surf harness and render fixtures) are NOT
copied: `fetch-inputs.sh` reads them with `git archive` at pinned commits into the
gitignored `.cache/`.

## Use

```sh
tools/parity/fetch-inputs.sh                       # or: --from-local ~/github-flux
# build the addons under test (release), copy each dylib to a .node file, then:
python3 tools/parity/parity.py run OUT --html2pdf h2p.node --html2pdf-svg h2p-svg.node --surf surf.node
python3 tools/parity/parity.py compare OUT b-main  # exit 0 = byte-identical
```

Self-test (no addons; run by CI): `python3 -m unittest discover -s tools/parity -p 'test_*.py'`
covers `compare`/`record`/`run` and checks the committed checkpoints and expected-diff files.

`compare` fails on any changed, added or removed output. A change that is intended
(a bug fix) is declared in an expected-diff file passed with `--expect`:

```json
{"id": "turbo-html2pdf#29", "reason": "style whole documents like Chrome", "control": "crates/turbo-dom-layout/tests/fixtures/html_document_chrome156.json",
 "changes": {"html2pdf": ["conformance-01-block-flow.pdf"], "surf": ["static-…png"]}}
```

Listed outputs that did not change fail as stale expectations, so every expectation
matches a real change. `changes` may only name outputs a checkpoint records (the
self-test checks it). Outputs of a NEW corpus input go in an `added` list instead,
e.g. `"added": {"html2pdf-extra": ["new-page.pdf"]}`: compare accepts them only as
additions (`NOT NEW` if the checkpoint already has the key, stale if it isn't produced),
and `record` keeps them in the next checkpoint. After a reviewed set of intended changes lands, record a new
checkpoint with `parity.py record OUT <name>`; later work (e.g. code-review fixes)
must then be zero-diff against it.

Checkpoints (`manifests/<name>/`): `b-main` (the released mains: turbo-dom 0.5.8,
turbo-html2pdf 0.3.9, turbo-surf 0.5.5), `b2-surf` (surf's binding re-vendored at
turbo-test@cb5c64e — equal to `b-main` for every corpus), `b-fixed` (every corpus after the
consolidation's bug-fix round: turbo-dom f860fea, turbo-html2pdf 55f623a, turbo-surf 27ed802;
equal to `b-main` plus the 883 declared changes of `expected/*.json`, so later work compares
against it with no expect files), and `b-0.6.0` (the surf corpora at the 0.6.0 release heads: turbo-dom 0189e4d,
turbo-surf 166d2d6; equal to `b-fixed` plus the 52 surf outputs declared by
`expected/r3-turbo-dom-142.json` and `expected/r3-turbo-dom-176.json`, 0 undeclared; its html2pdf corpora
are unchanged from `b-fixed`). Per-test cargo results for
`b-main` and `b2-surf` are in `manifests/<name>/tests/*.tsv`, produced by
`bin/baseline-cargo.sh` + `bin/cargo-results.py` (binary, test, result).

Environment for every run: rustc 1.98.0, `TZ=UTC LANG=C`, `RUSTY_V8_ARCHIVE` set to the
matching prebuilt V8 (simdutf for turbo-surf). Outputs depend on the host's fonts for
macOS-only fallbacks, so compare runs on the same host as the checkpoint.
