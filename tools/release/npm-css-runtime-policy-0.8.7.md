# Rust-owned npm CSS runtime policy (review candidate)

Additive optional `cssRuntimePolicyV1()` returns ABI1 JSON on native and WASM. No default is enabled by this increment. No CSS validity threshold, media behavior, font table or compatibility mode is supplied by JavaScript. The only backend-dependent field is the actual Scene font capability (`native_html_system` native, `bundled_html` wasm32).

The DTO matches the default assembler: preferences/environment; snapshot; selectorFacts; adapter compile/prepare/matching/contextualMatching/resolve/serialize/property/providerSnapshot; scene; composition; fonts. Existing endpoint units and field names remain unchanged.

Resource origins and conversions:

- `turbo_dom_layout::live` supplies node50,000, depth256, text/attribute byte2,000,000 and declaration500,000 caps directly. Text/attribute UTF16 unit allowances use the numeric byte allowance conservatively: UTF16 scalar unit count never exceeds UTF8 byte count. This is an allowance bound, not an assertion that all UTF8 inputs use identical memory. Raw lone units are accounted individually by the new boundary.
- Existing browser-env animation token computation is nesting16, per-output1,048,576 units and cumulative1,048,576 units. It is documented here without adding a V8 dependency.
- Existing layout native-source16MiB envelope becomes an **explicit new UTF16 backing allowance**:16,777,216 bytes /2 bytes per unit =8,388,608 units. It is not claimed equivalent to every former UTF8 source admission. Compile/input/retained aggregate policy uses this allowance. Counts sharing this cap are independent work/entry ceilings, not a claim about serialized-byte equality.
- Path and edge entry allowances are an explicit **aggregate serialized-u32 budget**,16MiB /4 bytes =4,194,304 entries. Physical paths, context-root chains and assigned-slot paths share their existing endpoint's aggregate charge. This is NOT a claimed bound derived from per-node depth: old capture resets depth at shadow roots and adds multiple path kinds. The ceiling can refuse earlier than a node/depth maximum, and is not a heap-size claim. Capture separately enforces native composed-depth256. No source-length arbitrary multiplier is used.
- Rule/prelude/selector counts share source-unit ceiling; each authored item requires source syntax. Sources/uses/roots/targets/requests are bounded by admitted nodes. Declaration/property/rollback entries use the existing declaration work ceiling. Aggregate matching/answer/domain/provider entries use the explicit envelope ceiling as a new resource admission cap. They are not browser CSS semantics.

Resource limits propagate existing typed failures; callers must not turn quota errors into invalid CSS/fallback. This does introduce finite limits to a formerly unbounded npm CSS mode: parent review and actual packed defaults/artifacts are required before enabling it.
